## Overview

This document tracks Python yfinance v1.7.0 parity work. Python yfinance 1.7.0
was released on 2026-08-26 from `3d9d2f0`. The audit baseline is the complete
upstream `1.6.0...1.7.0` comparison and changelog PR #2959, not only the short
release notes.

The Go branch starts from `main` at `94e7b45`, tagged `v1.6.1`. That baseline
already includes Go-specific authentication hardening, complete CycleTLS
cookie preservation, protobuf/WebSocket safety fixes, and cache immutability.
The v1.7.0 work must preserve those guarantees while adding only behavior that
maps from the upstream release.

## Current Go Gap Assessment

| Area | v1.6.1 behavior | v1.7.0 target |
| --- | --- | --- |
| Trading periods | `ChartMeta` has no typed schedule. `GetHistoryMetadata` returns cached metadata without fetching. | Add typed regular/pre/post periods and an explicit lazy accessor. Never introduce a hidden intraday request into normal daily history or fast-info calls. |
| Crumb degradation | `getWithCrumb` and six direct `AddCrumbToParams` call sites abort before the target request on every crumb error. | Degrade only rate-limit/network/timeout crumb failures for endpoints that can work without a crumb. Preserve non-transient auth failures and target error types. |
| Proxy preservation | `Client.proxy` is an immutable configuration snapshot passed to every CycleTLS request. | Keep implementation; add SOCKS5/SOCKS5h auth-and-target request regression coverage. |
| Split repair | Detection and volume confirmation are centered on one split boundary and correction can rescale the whole pre-split range. | Detect anomalous ranges and repair only missing/doubly adjusted ranges or cells. |
| Volume threshold | `volumeChangeThreshold` uses the v1.6 coefficient `0.333`. | Use the finalized v1.7 coefficient `0.2`, with regression tests. |

## Implementation Plan

### Phase 0: Exact upstream audit and API decision

- [ ] Read the complete patches for #2922, #2953, #2958 and their follow-ups,
  including upstream tests and both NRDY fixtures.
- [ ] Map every branch in `yfinance/data.py` and the relevant
  `history.py` functions to current Go call sites before editing code.
- [ ] Record Python-only packaging, test-infrastructure, and merge commits as
  N/A with evidence.
- [ ] Settle exported trading-period names and return shape before
  implementation. Check Go naming, zero-value behavior, JSON decoding shape,
  and whether callers need grouped regular/pre/post periods.
- [ ] Confirm whether the shared degradable request helper belongs in
  `pkg/client` or a small internal package so ticker, sector, industry, and
  calendars do not duplicate retry rules.

### Phase 1: Lazy typed trading periods

- [ ] Add typed schedule models that decode Yahoo regular/pre/post trading
  periods, including absent, sparse, and variant payload shapes.
- [ ] Preserve `Ticker.GetHistoryMetadata()` as a cache-only, no-network
  compatibility API.
- [ ] Add an explicit lazy accessor that first consumes cached intraday
  metadata; otherwise request `range=5d`, `interval=1h`, and
  `includePrePost=true` exactly once for concurrent successful callers.
- [ ] Merge only schedule/enrichment fields. Do not replace valid base chart
  metadata with a sparse enrichment response.
- [ ] Cache successful enrichment, preserve base metadata after failure, allow
  a later retry, and reset enrichment state in `ClearCache()`.
- [ ] Test: no hidden request from daily history/FastInfo, one first lazy
  request, successful cache hit, concurrent callers, sparse payload, failed
  enrichment preservation, retry after failure, and clear-cache behavior.
- [ ] Commit models/API separately from request/caching implementation where
  practical.

### Phase 2: Shared crumb degradation and proxy resilience

- [ ] Inventory and replace all current direct paths:
  `ticker.getWithCrumb`, sector, industry, calendars, ticker analysis,
  options, and both financials paths.
- [ ] Clone caller `url.Values` before adding or removing `crumb`; retries must
  never mutate caller state or leak a stale/empty crumb.
- [ ] Degrade crumb acquisition only when the error chain is rate-limit,
  network, or timeout related. Propagate invalid-response, parse, and other
  non-transient authentication failures.
- [ ] Send the target request without `crumb` after a degradable acquisition
  failure. A crumb endpoint 429 alone must not become a target rate-limit
  result.
- [ ] Preserve target semantics: target 429 remains `ErrRateLimit`; target
  timeout/network/status failures retain their typed classification.
- [ ] If upstream parity requires an alternate-strategy retry after target
  failure, cap it at one retry and ensure a secondary degradable crumb failure
  produces a crumb-less retry rather than an empty parameter.
- [ ] Prevent a concurrent crumb-refresh stampede and verify concurrent caller
  behavior with deterministic scripted clients.
- [ ] Prove `WithProxy("socks5h://...")` and config-provided SOCKS5 values are
  unchanged on auth and target requests. Do not add Python session ownership
  behavior that has no Go analogue.
- [ ] Cover upstream's six named cases plus non-transient failures,
  alternate-strategy retry, input immutability, no empty crumb, and
  concurrency.
- [ ] Commit shared request behavior and call-site migration independently.

### Phase 3: Range-based stock-split repair

- [ ] Import/adapt `NRDY-1d-bad-stock-split.csv` and its fixed output into
  `pkg/repair/testdata` with upstream attribution.
- [ ] Document the adaptation from Python's temporary fractional internal
  volume values to public integer `models.Bar.Volume` semantics.
- [ ] Detect contiguous anomalous ranges matching the split ratio or
  reciprocal, including isolated and alternating adjusted/unadjusted rows;
  do not require the price anomaly to occur on the split event row.
- [ ] Build representative positive-volume samples from adjacent candidate
  ranges and outside gaps, gathering useful samples beyond immediate boundary
  points where available.
- [ ] Denoise samples, compare inside/outside means, preserve the all-zero
  guard, and do not veto when a meaningful comparison cannot be calculated.
- [ ] Change the threshold to
  `1 + (splitMax - 1 + largestVolumeChangePct) * 0.2`.
- [ ] Correct only identified missing or double-adjusted ranges/cells; never
  blindly rescale every pre-split row in mixed data.
- [ ] Preserve forward/reverse split, dividend scaling, repaired markers, FX
  exclusion, false-positive resistance, and already-correct input behavior.
- [ ] Golden-test the full NRDY fixture and upstream last-27-row subset, and
  verify already-correct fixtures remain value-for-value unchanged.
- [ ] Keep fixture import, algorithm change, and verification fixes in
  reviewable commits.
