## Overview

This document tracks Python yfinance v1.8.0 parity work. Python yfinance 1.8.0
was released on 2026-11-03 from `e2f6104`. The audit baseline is the complete
upstream `1.7.0...1.8.0` comparison (44 non-merge commits), not only the
release notes.

The Go work starts from `main` at `52a04e8` (v1.7.0 plus the generated API
documentation commit). Unlike v1.7.0, each work item was developed on its own
branch and merged to `main` through its own pull request, so the audit trail is
one PR per behavior.

## Go-side Fixes Included in This Release

These are not upstream changes, but were found while auditing or verifying the
parity work and are needed for the 1.8.0 behavior to be correct.

| PR | Fix |
| --- | --- |
| #24 | Yahoo sends `downLast7Days` (capital D); `EPSRevision.DownLast7Days` was always 0. Counts are now read case-insensitively. |
| #19 | quoteSummary HTTP 429 now wraps `client.ErrRateLimit`, so `Tickers.Calendar` can stop after a rate limit. |
| #18 | `Screen` no longer writes predefined sort settings into the caller's `*ScreenerParams`. |
| #26 | Every live screener call failed (old `/predefined/<name>` URL returned HTML; POST had no crumb). Now `/predefined/saved?scrIds=` with cookie + crumb and Python's query parameters; HTTP errors wrap typed client errors. A live integration test was added. |
| #27 | Repair pipeline parity: unset `AdjClose` (0) no longer disables detection; History keeps null OHLC as NaN during repair; Repair always sees split/dividend events even with `Actions=false`; repair runs before AutoAdjust. Also fixes three dividend / zero-repair bugs exposed by the reorder (double adjustment of low-yield dividends, Adj Close drift in zero repair, per-dividend "too small" verdicts replaced by upstream's cluster vote). History without Repair is byte-identical to before. |

## Known Remaining Gaps

Recorded for later releases; none is a 1.8.0 upstream change.

- Dividend currency conversion (`_dividends_convert_fx`) is not implemented.
- FixZeroes interpolates whole bars, including partly null bars, where upstream
  rebuilds only bad cells from finer data or leaves NaN; `repairPartialZeroes`
  is not called.
- Without `KeepNA`, History drops null-price rows before repair and looks only
  at OHLC; upstream drops them after repair and also considers volume and
  actions.
- Only the "too small" dividend cluster vote is ported; the too-big, phantom
  and adjustment-exceeds-dividend votes are not.
- Reconstruction from finer intervals (15m/1h) is not implemented, so bars
  upstream rebuilds (e.g. some FX rows) differ.
- Minor review items: quoteSummary 404s are untyped errors; analysis/info
  caches return shared values callers can mutate; a `Repairer` is not safe for
  concurrent use (History creates one per call); with AutoAdjust, Go has no
  `back_adjust` or `rounding`.
