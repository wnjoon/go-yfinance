    go-yfinance v1.8.0 Development Progress

    Last Updated: 2026-11-04

    Tracking: go-yfinance issue #17

    Overview

    This document tracks Python yfinance v1.8.0 parity work. Python yfinance 1.8.0 was released on 2026-11-03 from e2f6104. The audit baseline is the complete upstream 1.7.0...1.8.0 comparison (44 non-merge commits), not only the release notes.

    The Go work starts from main at 52a04e8 (v1.7.0 plus the generated API documentation commit). Unlike v1.7.0, each work item was developed on its own branch and merged to main through its own pull request, so the audit trail is one PR per behavior.

    Go-side Fixes Included in This Release

    These are not upstream changes, but were found while auditing or verifying the parity work and are needed for the 1.8.0 behavior to be correct.

    PR Fix
    #24 Yahoo sends downLast7Days (capital D); EPSRevision.DownLast7Days was always 0. Counts are now read case-insensitively.
    #19 quoteSummary HTTP 429 now wraps client.ErrRateLimit, so Tickers.Calendar can stop after a rate limit.
    #18 Screen no longer writes predefined sort settings into the caller's *ScreenerParams.
    #26 Every live screener call failed (old /predefined/<name> URL returned HTML; POST had no crumb). Now /predefined/saved?scrIds= with cookie + crumb and Python's query parameters; HTTP errors wrap typed client errors. A live integration test was added.
    #27 Repair pipeline parity: unset AdjClose (0) no longer disables detection; History keeps null OHLC as NaN during repair; Repair always sees split/dividend events even with Actions=false; repair runs before AutoAdjust. Also fixes three dividend / zero-repair bugs exposed by the reorder (double adjustment of low-yield dividends, Adj Close drift in zero repair, per-dividend "too small" verdicts replaced by upstream's cluster vote). History without Repair is byte-identical to before.

    Verification

    Per-PR gates

    Every PR was rebased on the latest main before merge and passed gofmt, go vet, go test -race ./pkg/..., golangci-lint (v2.15.0, matching CI's latest), make docs, git diff --check, and remote CI (test, lint).

    Python differential testing

    • pkg/repair/testdata/oracle/gen_oracle.py runs upstream 1.8.0 and records detector masks, stage traces and repaired outputs for 472 split, unit-switch, level-shift, fixture and mined edge cases, plus NumPy reduction goldens. Go matches all of them (rtol 1e-9 for prices, exact for masks, volume, flags).
    • pkg/ticker/testdata/history_repair/gen_history_oracle.py runs upstream history() with the network mocked. Go's History matches it across all 16 Repair × Actions × AutoAdjust × KeepNA combinations (documented exception: Go's FixZeroes interpolates fully null rows that upstream leaves NaN).

    Pre-release verification on main

    After steps 1–8 merged, an extra verification pass ran on main before this release PR:

    • Coverage (go test -race -coverprofile): 70.4% overall; changed files news.go 96%, attrs.go 96%, screener.go 92%, analysis.go 80%, new repair files 97–99%.
    • Live Yahoo checks: News (three tabs, invalid tab), EPS methodology (MSFT, AAPL, NVDA), Tickers Info/Calendar, History repair on 15 tickers (1d and 1wk), and cmd/example. The screener failed live on both main and v1.7.0 code, which led to #26.
    • Two independent code reviews (repair, and everything else). Confirmed findings were fixed in #26 and #27; see the next section for the rest.
    • Live comparison after #27 (captured Yahoo data replayed through old main, the fix, and upstream 1.8.0): AAPL and NVDA match upstream exactly with Repair; SOXS matches; VOD.L with AutoAdjust went from ~41% off upstream to within 0.35%.

    Known Remaining Gaps

    Recorded for later releases; none is a 1.8.0 upstream change.

    • Dividend currency conversion (_dividends_convert_fx) is not implemented.
    • FixZeroes interpolates whole bars, including partly null bars, where upstream rebuilds only bad cells from finer data or leaves NaN; repairPartialZeroes is not called.
    • Without KeepNA, History drops null-price rows before repair and looks only at OHLC; upstream drops them after repair and also considers volume and actions.
    • Only the "too small" dividend cluster vote is ported; the too-big, phantom and adjustment-exceeds-dividend votes are not.
    • Reconstruction from finer intervals (15m/1h) is not implemented, so bars upstream rebuilds (e.g. some FX rows) differ.
    • Minor review items: quoteSummary 404s are untyped errors; analysis/info caches return shared values callers can mutate; a Repairer is not safe for concurrent use (History creates one per call); with AutoAdjust, Go has no back_adjust or rounding.

    Guardrails

    • Do not tag from a feature or release branch; tag only the verified merge commit on main.
    • Do not move or recreate an existing release tag.
    • Run make docs on a non-main branch: on main, gomarkdoc adds GitHub source links to every docs/api/*.md page.
    • Keep unrelated dirty files out of release commits.
